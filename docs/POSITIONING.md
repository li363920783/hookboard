# 定位：这是一个「解决一件事」的工具，不是平台

> 这份文件是定位口径，README / 文档 / 话术都以它为准。写代码的人（agent）也要读：
> **凡是让功能范围变大的想法，先来这里对照一遍。**

## 一句话

**把「有人让我改代码」这件事，从聊天窗口里捞出来，变成一条有状态、有审批、有记录的工作项。**

## 它解决的痛（真实场景，不是想象）

日常是这样坏的：

1. 缺陷在工单系统里（TAPD / Jira / GitHub issue），讨论在 IM 里，代码在编辑器里，**三处割裂**；
2. 让 AI agent 动手，你**不敢给它全权**——它能改生产库、能推错分支；
3. 于是变成"我盯着它干"，比我自己干还累；**手机上来一条消息，你只能回"等我到电脑前"**；
4. 干完了，谁批的、改了什么、什么时候能发版，**只剩聊天记录**，事后没人说得清。

## 它就做四步，多一步都不做

```
① 钩子进来      curl / webhook / CLI，任何系统都能把一条活推进来
② 派给 agent    你已经在用的那个（Claude Code / Codex / T3 / 任意 CLI）
③ 该点头就停    在你配置的节点上停下来，发一个链接给你，手机上点一下继续
④ 走完留痕      每一步都有时间、有谁批的、有结果；回写到你的工单系统
```

## 判断"这是不是好工具"的三条硬标准

这三条不过，功能再多都不算好工具：

1. **5 分钟能看到东西**：`docker run` 或 `pip install -e . && hookboard run`，打开一个页面，看到一条任务从"待处理"走到"等你审批"，点一下，它到"已完成"。**不需要先读三页文档、不需要先接任何真实系统。**
2. **接自己的系统 = 一个 30 行文件**：写一个 `Source` 适配器（或者干脆用 `generic` + 配置里的字段映射），加三行配置。做不到 30 行就说明抽象错了。
3. **断网也能用**：本地 SQLite、本地页面、审批靠链接。内网机器、飞机上、机房跳板机上都能跑。**这条决定它能不能进企业内网。**

## 明确的边界（越界就是变味）

| 不做 | 为什么 |
|---|---|
| 不做工单系统（不替代 Jira/TAPD） | 你有工单系统了，它只负责"接进来、写回去" |
| 不做 IDE / 不做代码编辑器 | 代码在编辑器里看，它只管流程 |
| 不内置模型调用 | agent 是别人的（Claude Code/Codex/任意 CLI），它只调命令行 |
| 不做多租户 / 权限体系 | 一个 `api_token` 够用；要多人协作请上正经平台 |
| 不做分布式 | 单机 SQLite 能撑一个人的全部工作流，撑不住就不该用它 |
| 不做 roadmap 承诺 | 个人维护的开源件，承诺 roadmap 是骗人 |

## 什么人会真的用它

- 一个人或小团队，**用 AI agent 改真实业务代码**，但**不能让 agent 自己说了算**；
- 代码在**内网**、系统是**老的自研后台**、IM 是**企业微信/飞书/钉钉**（不是 Slack 生态）；
- 想要的是"**把流程钉住**"，不是"再多一个 AI 聊天框"。

## 对自己（作者）的定位

- **第一目标是自用**：作者每天用它处理自己的工单流；
- 开源 = 让同类人不重复造；**不卖、不融资、不做 SaaS**；
- 维护承诺写实话：MIT、无 SLA、issue 尽力回、PR 欢迎但会为"保持小"而拒掉一半。
